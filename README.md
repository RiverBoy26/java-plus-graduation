# ExploreWithMe

## Архитектура проекта

**ExploreWithMe** - многомодульное Maven-приложение, разделённое на независимые Spring Boot микросервисы.

```text
.
├── core/
│   ├── user-service/       # пользователи
│   ├── event-service/      # события, категории и подборки
│   ├── request-service/    # заявки на участие
│   └── comment-service/    # комментарии
├── common/                 # общие DTO, исключения и компоненты
├── stats/
│   ├── stats-server/       # сохранение и получение статистики
│   ├── stats-client/       # HTTP-клиент статистики
│   └── stats-dto/          # DTO статистики
└── infra/
    ├── gateway-server/     # единая точка входа в API
    ├── discovery-server/   # Eureka Service Discovery
    ├── config-server/      # Spring Cloud Config Server
    └── config-repo/        # централизованные конфигурации
```

### Взаимодействие сервисов

Все внешние запросы направляются через **API Gateway** (`http://localhost:8080`), который перенаправляет их соответствующим микросервисам.

Для межсервисных запросов используются **OpenFeign** и обнаружение сервисов через **Eureka**:

- `event-service` запрашивает данные пользователей в `user-service` и количество подтверждённых заявок в `request-service`;
- `request-service` проверяет пользователей и события через `user-service` и `event-service`;
- `comment-service` получает данные автора и события через `user-service` и `event-service`;
- `user-service` может получать список событий пользователя из `event-service`.

Статистика событий обрабатывается через `stats-client` и `stats-server`. Каждый бизнес-сервис, а также `stats-server`, владеет собственной базой данных PostgreSQL.

Настройки хранятся в **`infra/config-repo/`**: конфигурации бизнес-сервисов — в `core/`, статистики — в `stats/`, инфраструктуры — в `infra/`, общие настройки — в `application.yaml`.

## Внутренний API

Внутренние эндпоинты предназначены для взаимодействия микросервисов и не являются частью внешнего клиентского API.

| Метод | Эндпоинт | Сервис | Назначение |
| --- | --- | --- | --- |
| `GET` | `/internal/users/{id}` | `user-service` | Получение пользователя по ID |
| `POST` | `/internal/users/batch` | `user-service` | Получение нескольких пользователей по списку ID |
| `GET` | `/internal/events/{id}` | `event-service` | Получение сведений о событии |
| `POST` | `/internal/requests/confirmed-counts` | `request-service` | Получение числа подтверждённых заявок по списку ID событий |

Пакетные методы используются для уменьшения числа HTTP-вызовов и предотвращения проблемы **N+1**. Для некритичных данных при недоступности зависимого сервиса предусмотрена деградация: например, `event-service` может отображать `0` подтверждённых заявок.

## Внешний API

Единая точка входа: **`http://localhost:8080`** (API Gateway). Основные внешние маршруты сохраняются при переходе от монолита к микросервисам.
